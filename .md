# eCommerce-php — Dúvidas e aprendizados

Essa documentação reúne as principais dúvidas que fui tendo enquanto desenvolvia meu projeto de e-commerce em PHP usando MariaDB e PDO.

A ideia aqui não é ser uma documentação super formal, mas sim um lugar para eu consultar depois e lembrar **o que cada coisa fazia, por que eu estava usando e quais erros eu tive durante o desenvolvimento**.

---

## 1. Como organizar as pastas do projeto?

Uma das primeiras dificuldades foi entender onde colocar cada coisa e principalmente como fazer um arquivo PHP encontrar outro.

A ideia que comecei a seguir foi separar o projeto por responsabilidade.

Exemplo:

```text
eCommerce-php/
│
├── assets/
│   ├── css/
│   ├── img/
│   └── js/
│
├── classes/
│   └── Produtos.php
│
├── config/

│
├── login_cadastro/

│   └── cadastro.php
│
├── produtos/
│   └── index.php
│
├── index.php
└── logout.php
```

### O que é `assets`?

`assets` normalmente é usado para guardar arquivos que fazem parte do visual e funcionamento do front-end:

* CSS
* JavaScript
* imagens
* fontes
* ícones

Por exemplo:

```text
assets/css/style.css
assets/js/script.js
assets/img/logo.png
```

# 2. O que é `require_once`?

Eu usei bastante isso para reutilizar arquivos PHP.

Exemplo:

```php
require_once 'config/Conexao.php';
```

Isso basicamente fala:

> “PHP, carregue esse arquivo aqui.”

O `once` serve para evitar que o mesmo arquivo seja carregado mais de uma vez.

Isso é importante principalmente quando estou trabalhando com classes.

---

# 3. Por que os caminhos dos arquivos davam tanto problema?

Uma das coisas que mais me confundiu foi o caminho relativo.

Por exemplo:

```php
require_once 'config/Conexao.php';
```

Esse caminho depende de **onde o arquivo que está executando o código está localizado**.

Se estou em:

```text
/index.php
```

posso fazer:

```php
require_once 'config/Conexao.php';
```

Mas se estou em:

```text
/produtos/index.php
```

provavelmente preciso voltar uma pasta:

```php
require_once '../config/Conexao.php';
```

O:

```text
../
```

significa:

> voltar uma pasta.

E:

```text
./
```

significa:

> pasta atual.

# 4. Como reutilizar a conexão com o banco?

Eu não queria ficar criando uma conexão com o banco em cada arquivo.

Por isso criei uma classe responsável pela conexão.

Exemplo da ideia:

```php
class Conexao
{
    private $host = 'localhost';
    private $db = 'ecommerce';
    private $usuario = 'root';
    private $senha = '';

    public function conectar()
    {
        $pdo = new PDO(
            "mysql:host={$this->host};dbname={$this->db}",
            $this->usuario,
            $this->senha
        );

        return $pdo;
    }
}
```

Depois, em outro arquivo:

```php
require_once 'config/Conexao.php';

$conexao = new Conexao();

$pdo = $conexao->conectar();
```

Assim eu consigo reutilizar a mesma lógica de conexão.

# 5. O que é PDO?

PDO significa **PHP Data Objects**.

É uma forma do PHP conversar com bancos de dados.

No meu projeto estou usando:

```text
PHP
 ↓
PDO
 ↓
MariaDB
```

O PDO também ajuda a trabalhar com `prepared statements`, que são importantes para evitar problemas como SQL Injection.

---

# 6. O que são Prepared Statements?

Eu tive bastante contato com isso nos códigos de login e pesquisa.

Em vez de montar uma SQL diretamente:

```php
$sql = "SELECT * FROM cadastro WHERE usuario = '$usuario'";
```

eu uso:

```php
$sql = "SELECT * FROM cadastro WHERE usuario = ?";
```

Depois:

```php
$stmt = $pdo->prepare($sql);

$stmt->execute([$usuario]);
```

O `?` funciona como um espaço reservado para o valor.

Isso deixa a consulta mais segura.

---

# 7. O que faz `prepare()`?

Quando faço:

```php
$stmt = $pdo->prepare(
    "SELECT * FROM cadastro WHERE usuario = ?"
);
```

estou preparando a consulta SQL.

O resultado fica armazenado em:

```php
$stmt
```

Depois posso executar:

```php
$stmt->execute([$usuario]);
```

---

# 8. O que faz `execute()`?

O `execute()` executa a consulta que foi preparada.

Exemplo:

```php
$stmt->execute([$usuario]);
```

Nesse caso:

```php
?
```

recebe:

```php
$usuario
```

Se tiver dois `?`:

```php
$stmt = $pdo->prepare(
    "SELECT * FROM produtos
     WHERE nome_produtos LIKE ?
     OR categoria LIKE ?"
);
```

posso passar:

```php
$stmt->execute([
    "%$texto%",
    "%$texto%"
]);
```

A ordem dos valores precisa acompanhar a ordem dos `?`.

---

# 9. O que faz `fetch(PDO::FETCH_ASSOC)`?

Essa foi uma parte importante no login.

Depois de executar:

```php
$verifica_login->execute([$usuario]);
```

eu posso pegar o resultado:

```php
$dados = $verifica_login->fetch(PDO::FETCH_ASSOC);
```

O:

```php
PDO::FETCH_ASSOC
```

faz o PHP retornar os dados como um array associativo.

Por exemplo, se o banco tiver:

```text
id_cadastro = 1
usuario = Bruno
email = teste@email.com
```

posso acessar:

```php
$dados['id_cadastro'];
$dados['usuario'];
$dados['email'];
```

---

# 10. Diferença entre `execute()` e `fetch()`

Uma coisa importante que aprendi:

### `execute()`

Executa a consulta.

```php
$stmt->execute();
```

### `fetch()`

Pega um resultado da consulta.

```php
$resultado = $stmt->fetch(PDO::FETCH_ASSOC);
```

Então normalmente fica:

```php
$stmt = $pdo->prepare("SELECT ...");

$stmt->execute();

$resultado = $stmt->fetch(PDO::FETCH_ASSOC);
```

# 12. O que é `$_POST`?

`$_POST` é uma variável especial do PHP usada para receber dados enviados por formulários usando:

```html
method="POST"
```

Exemplo:

```html
<form method="POST">
    <input type="text" name="usuario">
    <input type="password" name="senha">
</form>
```

No PHP:

```php
$_POST['usuario'];
$_POST['senha'];
```

O `name` do input é muito importante.

Se eu tiver:

```html
<input name="usuario">
```

vou receber:

```php
$_POST['usuario'];
```

# 13. O que é `$_GET`?

O `$_GET` pega informações que vêm pela URL.

Exemplo:

```text
produtos/index.php?q=mouse
```

Posso pegar:

```php
$q = $_GET['q'];
```

Nesse caso:

```php
$q
```

vai receber:

```text
mouse
```

---

# 14. Por que usar `??` com `$_GET`?

Eu também encontrei situações em que uma variável poderia não existir.

Em vez de:

```php
$cidade = $_GET['cidade'];
```

posso fazer:

```php
$cidade = $_GET['cidade'] ?? '';
```

Isso significa:

> Se `$_GET['cidade']` existir, use o valor. Caso contrário, use uma string vazia.

Isso ajuda a evitar:

```text
Undefined array key
```

---

# 15. O que faz `trim()`?

Exemplo:

```php
$cidade = trim($_GET['cidade'] ?? '');
```

O `trim()` remove espaços desnecessários no começo e no final.

Por exemplo:

```text
"   mouse   "
```

vira:

```text
"mouse"
```

---

# 16. O que faz `urlencode()`?

Uma dúvida que apareceu no desenvolvimento foi:

```php
$q = urlencode($_GET['q']);
```

O `urlencode()` transforma um texto para um formato seguro para ser colocado em uma URL.

Por exemplo, um texto com espaços ou caracteres especiais precisa ser codificado.

Exemplo conceitual:

```text
mouse gamer
```

pode virar algo como:

```text
mouse+gamer
```

Isso é útil quando estou passando uma pesquisa através da URL.

# 20. O que é `INNER JOIN`?

O `INNER JOIN` serve para juntar informações de tabelas relacionadas.

Eu tinha:

```text
categorias
```

e:

```text
produtos
```

O produto possuía uma chave estrangeira apontando para a categoria.

Então:

```sql
INNER JOIN categorias c
ON p.fk_categorias_id = c.id_categorias
```

significa basicamente:

> Junte o produto com a categoria correspondente.

# 21. O que significa `WHERE`?

`WHERE` serve para colocar uma condição na consulta.

Exemplo:

```sql
SELECT *
FROM produtos
WHERE preco_produtos > 100;
```

Aqui só serão retornados produtos cujo preço seja maior que 100.

# 22. O que significa `AND`?

`AND` significa que duas condições precisam ser verdadeiras.

Exemplo:

```sql
WHERE usuario = ?
AND senha = ?
```

A consulta procura algo que tenha:

```text
usuario correto
E
senha correta
```

# 23. O que significa `OR`?

`OR` significa “ou”.

Exemplo:

```sql
WHERE nome_produtos LIKE ?
OR nome_categorias LIKE ?
```

Nesse caso, o resultado pode aparecer se:

```text
nome do produto bater
OU
nome da categoria bater
```

# 26. Hash de senha

Uma das partes que mais deu problema foi o sistema de senha.

Eu aprendi que não devo guardar a senha pura no banco.

Em vez de:

```php
$senha = $_POST['senha'];
```

e salvar diretamente:

```text
123456
```

uso:

```php
$senhaHash = password_hash(
    $senha,
    PASSWORD_DEFAULT
);
```

O banco passa a guardar algo parecido com:

```text
$2y$...
```

em vez da senha original.

---

# 27. `password_hash()` e `password_verify()`

Essas duas funções trabalham juntas.

No cadastro:

```php
$hash = password_hash(
    $senha,
    PASSWORD_DEFAULT
);
```

Salvo o hash no banco.

No login, não faço:

```sql
WHERE senha = ?
```

comparando diretamente a senha digitada com o hash.

Eu pego o hash salvo:

```php
$dados = $stmt->fetch(PDO::FETCH_ASSOC);
```

Depois:

```php
password_verify(
    $senha,
    $dados['senha']
);
```

A função verifica se a senha digitada corresponde ao hash.

---

# 28. O problema do tamanho da coluna `senha`

Tive um problema em que `password_verify()` estava retornando `false` mesmo quando a senha parecia estar correta.

O problema estava relacionado ao tamanho da coluna do banco.

O hash gerado pelo `password_hash()` precisa caber inteiro na coluna.

Por isso:

```sql
senha VARCHAR(255)
```

é uma escolha adequada.

Se o banco cortar o hash, a verificação não vai funcionar.

Nesse caso, foi necessário corrigir a coluna e cadastrar a senha novamente.

# 34. O que faz `header()`?

Usei `header()` para redirecionar o usuário.

Exemplo:

```php
header('Location: ../index.php');
```

Isso manda o navegador para outra página.

Normalmente, depois de um redirect, é interessante usar:

```php
exit;
```

para impedir que o restante do código continue sendo executado.

---

# 35. Por que o `header()` dava problema?

Uma coisa importante:

```php
header()
```

não pode ser enviado depois que o PHP já começou a mandar conteúdo para o navegador.

Por isso é importante evitar:

```php
echo "alguma coisa";
```

antes do:

```php
header('Location: ...');
```

Também é preciso tomar cuidado com espaços ou HTML enviados antes do `header()`.

# 39. Diferença entre classe e objeto

No projeto comecei a separar algumas responsabilidades em classes.

# 40. Passando o PDO para uma classe

Uma coisa que comecei a fazer foi passar a conexão para a classe.

Exemplo:

```php
$produto = new Produtos($pdo);
```

Dentro da classe:

```php
class Produtos
{
    private $pdo;

    public function __construct($pdo)
    {
        $this->pdo = $pdo;
    }
}
```

Assim a classe `Produtos` consegue usar a conexão que já foi criada.

# 41. O que é `$this`?

Dentro de uma classe:

```php
$this
```

representa o próprio objeto.

Por exemplo:

```php

```

significa:

> o atributo `pdo` deste objeto.

Se no construtor faço:

```php
$this->pdo = $pdo;
```

estou guardando o PDO dentro do objeto.

# 42. O que é `private`?

Quando tenho:

```php

```

significa que esse atributo pertence à classe e não deve ser acessado diretamente de fora dela.

Por exemplo, a ideia é usar:

```php
$this->pdo
```

dentro da própria classe.

}

# 44. O erro de SQL com vírgula

Em uma das consultas que montei apareceu algo parecido com:

```sql
SELECT
    c.nome_categorias,
    p.nome_produtos,
    p.preco_produtos,
FROM produtos p
```

O problema é a vírgula depois de:

```sql
p.preco_produtos,
```

Não pode existir uma vírgula antes do `FROM`.

O correto é:

```sql
SELECT
    c.nome_categorias,
    p.nome_produtos,
    p.preco_produtos
FROM produtos p
```

# 47. O que eu aprendi com os erros

Grande parte do aprendizado veio dos erros.

Alguns exemplos:

### `Undefined variable`

Normalmente significa que tentei usar uma variável antes de definir.

### `Undefined array key`

Normalmente significa que tentei acessar algo como:

```php
$_POST['usuario']
```

sem o formulário realmente ter enviado esse campo.

### Erro no `require_once`

Normalmente significa que o caminho do arquivo está errado.

### `password_verify()` retornando `false`

Pode acontecer se:

* a senha estiver errada;
* o hash não corresponder;
* o hash tiver sido armazenado incorretamente;
* a coluna do banco tiver cortado o hash.

### Erro no SQL

Pode ser:

* vírgula sobrando;
* nome de tabela errado;
* nome de coluna errado;
* `JOIN` incorreto;
* quantidade de `?` diferente da quantidade de valores no `execute()`.

# 48. O que eu ainda preciso prestar atenção

Durante o desenvolvimento, algumas coisas ficaram como pontos importantes para eu não esquecer:

* Sempre conferir o caminho dos `require_once`.
* Conferir os nomes dos `name` dos inputs.
* Conferir se estou usando `$_GET` ou `$_POST` corretamente.
* Usar `prepare()` e `execute()` nas consultas.
* Não guardar senha pura no banco.
* Usar `password_hash()` no cadastro.
* Usar `password_verify()` no login.
* Garantir que a coluna da senha comporte o hash.
* Usar `session_start()` antes de trabalhar com `$_SESSION`.
* Conferir os dados retornados pelo `fetch()`.
* Conferir se existem vírgulas extras nas consultas SQL.
* Conferir a quantidade de `?` e parâmetros do `execute()`.
* Tomar cuidado com `header()` depois de algum conteúdo já ter sido enviado.
* Usar `htmlspecialchars()` ao exibir dados vindos do usuário.
* Manter a conexão com o banco centralizada em uma classe.
* Passar o `$pdo` para as classes que precisam acessar o banco.
